# KI: Knowledge Workflows

## Overview
Исполняемые инструкции (Workflows) для ИИ-агентов, определяющие стандартные процедуры обслуживания базы знаний и управления изменениями.

## Key Workflows

### Maintenance
| Workflow | Trigger | Action |
|---|---|---|
| `/sync-knowledge` | После изменений в коде. | Синхронизация хешей, обновление `DIR_INDEX.md` и `AGENTS.md`. |
| `/expand-knowledge` | При появлении нового модуля. | Аудит покрытия -> Выбор цели -> Создание/разделение KI. |
| `/update-knowledge` | Плановое обновление. | Комбинированный процесс расширения и синхронизации. |

### Architectural Decisions
| Workflow | Purpose | Details |
|---|---|---|
| `/create-adr` | Фиксация решений. | Создание нового файла в `decisions/` с описанием контекста и последствий. |

## Structure & Rules
- **Turbo-all / Turbo**: Аннотации в Markdown, разрешающие агенту автоматически запускать команды `run_command` без явного подтверждения пользователя (в безопасных пределах).
- **Tool Constraints**: Ворклоу строго ограничивают используемые инструменты (только встроенные или специфичные MCP).

## Non-obvious Details
- **Step Atomicity**: Каждый шаг ворклоу спроектирован так, чтобы быть атомарным. При сбое агент должен иметь возможность возобновить работу с прерванного шага.
- **Verification Loop**: Большинство ворклоу заканчиваются шагом `audit_coverage` для подтверждения того, что действия не ухудшили качество документации.

## Common Pitfalls
- **Skipping Steps**: Пропуск шага регистрации в `doc_config.json` при создании KI делает его невидимым для системы аудита.
- **Manual Overwrite**: Ручное редактирование файлов в `.know/` вне ворклоу может привести к рассинхронизации стейта.
