# ADR 049: Удаление дистилляции учителя (logic_loss) из Phase 3

## Context and Problem
В процессе Phase 3 (DUS Training) наблюдалась стагнация метрики `identity_penalty` на уровне 0.5 (cos ≈ 0.5), несмотря на высокий вес в loss-функции (5.0). Анализ показал наличие фундаментального архитектурного конфликта, заложенного в ADR 042.

Модель получала противоречивые градиенты для чистых (не-зашумленных) токенов:
1. `identity_penalty` требовал на 40-м слое прокинуть вектор `z_clean` (из топологии Qwen/LatentEncoder) без изменений (работа в качестве identity-функции).
2. `logic_loss` (Pearson RKD, вес 1.0) требовал на 33-м слое трансформировать вектор так, чтобы его относительная геометрия совпала с геометрией 23-го слоя DeepSeek-R1-7B.

Эти два требования заставляли сеть формировать "зигзагообразную" траекторию: `Qwen Space -> DeepSeek Space (layer 33) -> Qwen Space (layer 40)`. Не обученный с нуля 40-слойный трансформер (инициализированный ModernBERT) с трудом справлялся с задачей обратного проецирования глубокой логики DeepSeek в сжатое пространство Qwen за 7 финальных слоев.

## Decisions Made and Lessons Learned
- **What was tried and didn't work:** Попытка объединить задачу денойзинга в латентном пространстве (Qwen) с дистилляцией логики из другой модели (DeepSeek) через промежуточные слои. Это привело к перегрузке capacity модели и конфликту градиентов.
- **Successful Solution (Best Practice):** Полный отказ от дистилляции учителя (`logic_loss`) на этапе Phase 3. Учитель (DeepSeek-R1-7B) полностью удален из тренировочного скрипта.

Теперь модель DUS фокусируется на 100% на задаче денойзинга:
- Восстанавливать `z_clean` для зашумленных токенов (`denoise_loss`).
- Прокидывать `z_clean` без изменений для уверенных/чистых токенов (`identity_penalty`).

Обучение логике будет происходить *неявно* (implicitly), как в классических диффузионных моделях (DiT, Stable Diffusion): чтобы правильно восстановить сильно зашумленный токен, сеть сама вынуждена глубоко анализировать контекст и выстраивать логические связи, без принудительного копирования чужой геометрии.

## Impact
- **Позитивный:** Разрешен конфликт градиентов. Ожидается пробитие плато метрики `identity_penalty`.
- **Позитивный:** Значительная экономия VRAM (не загружаются 14 ГБ весов bfloat16 DeepSeek).
- **Позитивный:** Значительное ускорение обучения (tokens/sec), так как удален тяжелый forward pass через 30 слоев 7B-модели на каждом шаге.
