# ADR 046: Интеграция Confidence Embedding в Identity и Denoise Loss, исправление EMA

## Context and Problem
В процессе анализа результатов первого прогона Phase 3 (Logic & Denoising) были выявлены две проблемы:
1. **EMA не обновлялся:** Loss валидации оставался константным на уровне инициализации. Это произошло из-за XLA Dead Code Elimination (DCE). Операции обновления `shadow`-весов (`ema.step()`) не материализовывались, так как компилятор не видел их использования до фазы валидации.
2. **Застревание `identity_penalty`:** Loss `identity_penalty` перестал сходиться. DUS получал на входе `z_noisy + c_embed`, а цель `identity` стояла `z_noisy`. Residual connection сети возвращал `(z_noisy + c_embed) + corrections`. Таким образом, чтобы вернуть `z_noisy`, сети приходилось выучивать `-c_embed` (уничтожать свой собственный conditioning). Это повторяло проблему двойного residual (ADR 044). Та же логика распространялась на `denoise_loss`, где сеть пыталась восстановить `z_clean`, борясь с собственным `c_embed`.

## Decisions Made
1. **Фикс EMA (XLA):** Добавлен принудительный барьер материализации `xm.mark_step()` после вызова `ema.step()`, чтобы `shadow`-веса обновлялись синхронно на TPU. Внедрена метрика `ema_diff` для контроля отрыва теней от горячих весов.
2. **Сдвиг таргетов:** В соответствии с архитектурной задумкой, `c_embed` теперь рассматривается как полезный аддитивный сигнал, который проходит сквозь трансформер (сохраняется) и будет удаляться уже внешним Оркестратором перед передачей в голову.
   - `identity_target = safe_normalize(z_noisy + c_embed)`
   - `denoise_target = safe_normalize(z_clean + c_embed)`
   
   Это устраняет конфликт. Теперь для чистого токена цель `identity_target` полностью совпадает с выходом тривиального residual: `output = input`.

## Impact
- **Ожидаемый:** Восстановление сходимости `identity_penalty` и `denoise_loss`, так как модели больше не нужно инвертировать `c_embed`.
- **Ожидаемый:** Валидация через EMA станет информативной и более гладкой.
