# ADR 041: Переход на Angular Loss и строгую сферическую топологию для DUS (Phase 3)

## Context and Problem
В Phase 3 (DUS Logic Training) наблюдалась проблема: выход DUS сходился к "ортогональному решению", а метрики `denoise_loss` и `identity_penalty` зависали на плато (достигая предела точности `bfloat16`). 
Анализ показал две архитектурные ошибки:
1. Выход DUS (`dus_final`) не нормализовывался, в то время как весь пайплайн (начиная с Phase 1 VAE) предполагал работу со строго единичной сферой. Это позволяло DUS "читерить" с нормой вектора для минимизации потерь.
2. Использование `F.huber_loss` (L2) для денойзинга на сфере неэффективно и конфликтовало с Pearson RKD (`logic_loss`), который инвариантен к вращению. В результате пространство вращалось ортогонально ожидаемому.

## Decisions Made and Lessons Learned
- **Что пробовали и не сработало:** `F.huber_loss` в связке с RKD без жесткой фиксации радиуса векторов. `prior_loss` (variance/covariance) не мог удержать геометрию от коллапса без явной нижней границы (variance floor).
- **Successful Solution (Best Practice):** 
  - Жестко ограничить `dus_final` на единичную сферу: `safe_normalize(dus_final.float(), dim=-1).to(bfloat16)`.
  - Полностью заменить Huber Loss на Angular Loss (`1.0 - cos_sim`) для `denoise_loss` и `identity_penalty`, чтобы напрямую штрафовать отклонение по углу.
  - Кастовать тензоры к `float32` перед вычислением косинусного сходства для устранения плато квантования `bfloat16`.
  - Добавить `var_floor = 1.0 / (D * 2)` в `prior_loss`, чтобы предотвратить коллапс дисперсии координат на сфере.

## Impact
- **Позитивный:** DUS будет изучать семантическое выравнивание векторов без искажения их длины. Лоссы напрямую отражают угловую точность. Устранены артефакты `bfloat16`.
- **Негативный:** Модель больше не имеет свободы в масштабировании векторов для минимизации потерь, что может потребовать более аккуратной настройки `learning_rate` из-за более жесткого ландшафта на сфере.
