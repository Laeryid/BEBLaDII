# ADR 034: Угловая функция потерь для OutputProjector (Phase 3)

## Context and Problem

OutputProjector (OP) обучался маппировать пространство L40 (выход DUS) обратно в сферическое пространство X0 (выход `InputProjector.proj`, LayerNorm, норма ≈ 32). Обе точки — L40 (около-сферическое после отбеливания) и X0 (точная сфера) — определяются направлением, а не длиной вектора. Тем не менее в качестве функции потерь использовался **Huber-loss в евклидовых координатах**.

Проблема: Huber минимизирует XYZ-расстояние между точками, а не угловое отклонение. На сфере при одинаковых нормах cos_sim слабо коррелирует с евклидовой ошибкой. Это привело к ложному плато:
- `loss_huber ≈ 0.009` (выглядит хорошо)
- `cos_sim ≈ 0.81` (фактически 11° углового отклонения — плохо)

При тест-цикле `gravity → OP → DUS → OP → ...` на Cycle 1 cos=0.999 в L40, но выход OP не попадает в правильную окрестность словаря, что ломает рекурсию.

## Decisions Made and Lessons Learned

- **Что не работало:** `HuberLoss(Z_pred, Z_hat_target)` в декартовых координатах. Модель достигала плато cos≈0.81 и переставала улучшаться, несмотря на низкое значение loss.

- **Успешное решение:** Замена функции потерь на угловую с опциональным штрафом за норму. Реализовано через параметр `--loss-mode` в `train_phase3.py`:

  ```python
  # Угловая компонента (основная)
  Z_pred_norm = F.normalize(Z_pred, dim=-1)
  Z_tgt_norm  = F.normalize(Z_hat_target, dim=-1)
  cos_loss = 1.0 - (Z_pred_norm * Z_tgt_norm).sum(dim=-1).mean()

  # Штраф нормы (вспомогательный, для cosine+norm режима)
  norm_penalty = HuberLoss(Z_pred.norm(dim=-1), Z_hat_target.norm(dim=-1))
  loss = cos_loss + 0.05 * norm_penalty
  ```

- **Три режима для аблации** (`--loss-mode`):
  | Режим | Потеря | Назначение |
  |---|---|---|
  | `huber` | Huber в XYZ | Baseline (контрольная точка) |
  | `cosine` | `1 - cos_sim` | Чистая угловая, без нормы |
  | `cosine+norm` | `cos_loss + 0.05·huber(norm)` | **Рекомендуется** (ADR-033 сфера) |

- **Новая метрика `train/cos_sim`** добавлена в WandB как основной индикатор качества OP. Старый `train/huber` теперь логируется только в режиме `huber`.

- **Диагностика рекурсии:** Причина деградации при Cycle ≥ 2 — out-of-distribution вход DUS. DUS обучался получать `mu_head(h_реального_токена)`, а при рекурсии получает `mu_head(OP_out)`. Это отдельная проблема (возможная доработка первых слоёв DUS), не блокирующая Phase 3.

## Impact

- **Позитивно:** Функция потерь теперь напрямую оптимизирует целевую метрику (cos_sim). Ожидается прорыв плато с 0.81 до >0.95 при переобучении с `--loss-mode cosine+norm`.
- **Позитивно:** `--norm-weight 0.05` удерживает норму OP-выхода вблизи 32 (требование ADR-033 для совместимости с `mu_head` и DUS).
- **Нейтрально:** Требуется переобучение OP с новой функцией потерь на Kaggle/TPU. Старый чекпоинт `OP_tau_007_layers_3.pt` остаётся валидным baseline для сравнения.
- **Негативно:** При режиме `cosine` (без штрафа нормы) возможен дрейф нормы выхода OP, что нарушает масштаб для `mu_head`. Поэтому `cosine+norm` рекомендуется как production-режим.
