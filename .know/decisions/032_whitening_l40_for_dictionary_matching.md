# ADR 032: Whitening пространства L40 для Soft Dictionary Matching

## Context and Problem

В ходе первого пробного прогона Phase 3 (tau=0.05, k=28) метрика k_eff оказалась равной **27.6 из 28** — Softmax выдаёт практически равномерное распределение по всем соседям. Это означает, что алгоритм не способен выделить семантически значимых соседей, и все токены словаря имеют почти одинаковое косинусное сходство с запросом.

**Причина:** Пространство L40 имеет rank1_ratio ≈ 0.7, то есть ~70% длины вектора уходит в одну доминирующую компоненту. После `F.normalize()` все векторы проецируются в узкую область гиперсферы (все стянуты к одному "полюсу"). Разница между косинусным сходством первого и 28-го соседа исчезающе мала (например, 0.9991 vs 0.9988), и даже при низкой температуре τ=0.05 Softmax не может "растянуть" эту разницу.

**Важный вывод из анализа:** Проблема не в температуре — она в самой геометрии пространства. Понижение τ до 0.01 и ниже даёт лишь частичное улучшение.

## Decisions Made and Lessons Learned

### Решение: Диагональное отбеливание (Whitening) перед поиском соседей

Применяем Z-score стандартизацию по каждой оси пространства L40, используя статистику глобального словаря D_L40:

```python
# Вычисляется один раз при старте — по всему словарю D_L40.pt
whitening_mu    = D_L40.mean(dim=0, keepdim=True)   # глобальный центр
whitening_sigma = D_L40.std(dim=0, keepdim=True) + 1e-6  # std по каждой оси

# Сферический словарь: отбеливаем и нормируем
D_L40_sphere = normalize((D_L40 - whitening_mu) / whitening_sigma, dim=-1)

# В цикле обучения: те же "очки" на запросы
L40_sphere = (L40_flat - whitening_mu) / whitening_sigma
L40_norm = normalize(L40_sphere, dim=-1)
scores = (L40_norm @ D_L40_sphere.T) / tau
alpha = softmax(topk(scores, k=28), dim=-1)

# Сборка Z_hat из ОРИГИНАЛЬНЫХ векторов D_X0 (не сферических!)
Z_hat = ...  # как в ADR 031 — alpha не меняет смысла для D_X0
```

### Теоретическое обоснование корректности

Отбеливание **не меняет семантическую структуру соседства**, а лишь масштабирует оси:
- Доминирующая компонента (σ ≈ большое) сжимается.
- Слабые семантические оси (σ ≈ малое) усиливаются.
- Токены, которые различались только по тонким семантическим осям, теперь будут расположены дальше друг от друга на сфере.

Веса `alpha`, вычисленные в сферическом пространстве L40, остаются **релевантными для D_X0** (пространство Qwen), так как:
1. D_L40 и D_X0 — парные словари (одни и те же токены)
2. Семантическое соседство в L40 коррелирует с семантическим соседством в D_X0 (это базовая гипотеза Phase 2, которую мы обучали соблюдать)
3. Whitening только "выравнивает масштаб осей" для поиска, не меняя топологию соседства

### Эффективная температура

Whitening эквивалентно уменьшению эффективной температуры, так как расстояния между токенами на сфере после отбеливания становятся больше. Это означает, что при том же τ=0.05 Softmax будет давать более острые пики. Нужно мониторить k_eff и при необходимости повышать τ.

### Что НЕ стали делать

- **PCA-проекция**: требует хранения матрицы поворота, усложняет код, не даёт принципиального преимущества перед диагональным отбеливанием
- **Центрирование по батчу**: нестабильно (зависит от конкретного батча), словарь и запросы были бы в разных системах координат
- **Изменение пространства D_X0**: было рассмотрено и отклонено — мы не хотим трогать цель разложения, только "прицел" для поиска

## Impact

- k_eff ожидается в диапазоне 2–10 вместо 27.6
- Whitening mu/sigma вычисляются один раз при загрузке (не влияют на скорость обучения)
- Параметр τ требует повторной калибровки после включения whitening
- Потенциальный риск: если sigma какой-то оси близко к 0 (мёртвая ось), деление усилит шум. Защита: `+ 1e-6` к sigma.
