# ADR 052: Изоляция замороженных генераторов таргетов в режиме eval()

## Context and Problem
В процессе анализа логов Phase 3 был выявлен катастрофический разрыв между `train/loss` (~7.0) и `val/loss` (~14.05). Анализ показал, что EMA работает корректно (отставание плато `ema_diff` составило всего `0.00012`), поэтому проблема крылась в сдвиге распределения на валидации.

Обнаружилось, что замороженный `LatentEncoder`, который используется в качестве генератора "чистых" таргетов `z_clean`, **не переводился явно в режим `.eval()`**. 
Поскольку фреймворк глобально вызывает `model.train()` для всей сети во время обучения, `LatentEncoder` также переходил в режим обучения. Это активировало Dropout-слои (10%) внутри его 40 блоков ModernBERT. 
В результате:
1. Во время обучения сеть DUS тренировалась попадать в **зашумленные** векторы `z_clean` (сдвинутые Dropout'ом).
2. На валидации глобальный `model.eval()` отключал Dropout везде, включая `LatentEncoder`. 
3. Целевой базис `z_clean` мгновенно "телепортировался" в другую часть 1024-мерного пространства, что приводило к обрушению косинусных метрик (`identity_penalty` и `denoise_loss`), так как выход обученной сети больше не совпадал с чистыми таргетами.

## Decisions Made
- **Forced `eval()` for Frozen Generators:** Все замороженные подмодели (`LatentEncoder`, `qwen_embeddings`), выступающие в роли эталонов или генераторов таргетов, обязаны всегда находиться в режиме `.eval()`.
- **Override `train()` Method:** Для предотвращения случайного перевода генераторов в режим обучения при глобальном вызове `model.train()`, необходимо переопределять метод `train()` в оркестраторах (например, `Phase3Orchestrator`):
  ```python
  def train(self, mode=True):
      super().train(mode)
      # Форсируем eval для замороженных модулей
      if hasattr(self, 'encoder'):
          self.encoder.eval()
      if hasattr(self, 'qwen_embeddings'):
          self.qwen_embeddings.eval()
  ```

## Impact
- Устранен скрытый двойной Dropout-шум, искажавший геометрическую цель обучения (target manifold).
- Устранен искусственный сдвиг распределения между фазами `train` и `val`. Метрика `val/loss` теперь будет корректно отражать реальное качество работы DUS на чистых эмбеддингах.
