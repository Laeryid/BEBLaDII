# Идея для Фазы 4: Relative Processing (Базис на основе `mu` из VAE)

## Контекст
В Фазе 4 планируется добавление Cross-Attention (CA) слоев внутрь latentBERT для интеграции статического контекста вопроса (Prompt-CA) и работы с неуверенностью (Confidence Head). Векторами `Keys` и `Values` для этих CA-слоев будут служить изначальные эмбеддинги, прошедшие через `InputProjector` (VAE).

`InputProjector` генерирует для каждого токена базовое математическое ожидание `mu` и дисперсию `sigma` (через `logvar`). 

## Описание идеи
Вместо того чтобы центрировать косинусный лосс вычитанием среднего по батчу/последовательности, мы можем **центрировать выходы внутренних слоев вычитанием их собственного `mu`**:

```python
h_centered = raw_lX - mu.detach()
```

## Почему это элегантно
1. **Relative Reasoning:** Внутренние слои сети (L20, L30, L40) будут физически моделировать не абсолютное значение токена, а исключительно его **эволюцию (дельту)** относительно изначального входного смысла (`mu`). Студент учится только тому, "что нового он понял" о токене в процессе рассуждения.
2. **Идеальная среда для Attention:** Будущие CA-слои получат идеальную чистоту пространства. Attention (через Query) будет работать исключительно по векторам "смысловых сдвигов", а не бороться с огромными базовыми значениями токенов.
3. **Единая система координат:** Вся сеть прочно привязывается к единой системе координат (определяемой VAE на входе), что исключает дрейф латентного пространства на глубоких слоях.

## Почему отложено до Фазы 4
В Фазе 1 `mu` является **живым параметром** (InputProjector активно обучается). Если мы начнем явно вычитать `mu` из скрытых состояний в лоссе, это создаст жесткую двустороннюю зависимость:
*   $\partial L / \partial raw\_lX$ будет зависеть от $mu$.
*   $\partial L / \partial mu$ будет искажаться градиентами от дистилляции.

Оба параметра начнут "гнаться друг за другом", что приведет к нестабильности (особенно на плато).

**План внедрения (Фаза 4):**
Реализовывать этот механизм не как лосс-функцию, а как архитектурное решение (skip-connection) внутри самих CA-слоев: Query для CA будет вычисляться именно как `h_l - mu.detach()`. Это сделает архитектуру похожей на U-Net, где глубокие слои обрабатывают дельты относительно поверхностных.
