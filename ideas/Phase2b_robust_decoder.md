# Идея: Phase 2b — Обучение устойчивого декодера

**Дата:** 2026-07-26  
**Статус:** Идея (не реализована)  
**Зависимость:** Проводится после Phase 3 (DUS checkpoint нужен для генерации данных)

---

## Проблема

`ModernLatentDecoder` после Phase 2 идеально реконструирует чистые выходы энкодера, но катастрофически хрупок:
- При шуме eps=0.05 cos_sim выходов падает с ~0.93 до ~0.40
- SLERP-интерполяция выдаёт грамматический мусор на промежуточных шагах
- DUS на инференсе никогда не выдаёт идеальный z_0 → декодер ломается

**Корень проблемы:** декодер выучил таблицу соответствий для точных точек на сфере, а не гладкую функцию.

---

## Решение

### 1. Аугментация входных данных (три источника)

| Источник | Доля | Описание |
|----------|------|----------|
| Clean | 30% | `z_clean` из энкодера (как в Phase 2) |
| Spherical Noise | 40% | `z_noisy = slerp(t, z_clean, ε)`, ε ~ Uniform(S^{d-1}) |
| DUS-denoised | 30% | `z_clean → зашумить → DUS(z_noisy, t)` (реальные артефакты диффузии) |

Target tokens **всегда** от оригинального текста — даже при зашумлённом z.

### 2. Функция потерь

```
L_total = L_CE + λ * L_vocab
```

**L_CE** — стандартный CrossEntropy на оригинальные токены:
```python
logits = lm_head(decoder(z_augmented))
L_CE = CrossEntropy(logits, original_token_ids, mask=attention_mask)
```

**L_vocab** — притяжение к ближайшему токену словаря (Soft VQ / Commitment Loss).  
Реализуется через уже вычисленные logits — без перебора 151936 токенов:
```python
τ = 0.1  # малая температура → жёсткое притяжение к одному токену
soft_weights = F.softmax(logits.detach() / τ, dim=-1)  # (B, T, V)
soft_embed = soft_weights @ lm_head_weight              # (B, T, 1536)
# soft_embed = "консенсусный" токен-вектор по мнению модели

L_vocab = 1.0 - cosine_similarity(decoder_out, soft_embed.detach()).mean()
```

**Почему L_vocab нужен, если есть L_CE:**
- CE тянет к *конкретному правильному* токену — при сильном шуме создаёт непреодолимое противоречие
- L_vocab тянет к *любому валидному* токену словарного многообразия — разрешает это противоречие
- Разделение: CE отвечает за «что», L_vocab — за «быть словом вообще»

**Почему НЕ нужен L_smooth** (притяжение к одинаковому выходу для соседних z):  
Языковые переходы резкие. «Кошка лежит» → «собака лает» — соседние z должны выдавать *разные, но грамматичные* слова. L_smooth усреднял бы их, создавая мусор.

### 3. Морфология и синтаксис

Явно обучать им не нужно — ModernBERT-large уже знает грамматику из предобучения.  
Noisy CE + bidirectional attention создадут нужный сигнал: *«при шумном z — посмотри на соседние позиции через attention, реши что грамматично подходит»*.

### 4. Curriculum по шуму

| Этап | Steps | Noise range t | DUS-denoised |
|------|-------|---------------|--------------|
| Warm-up | 0–500 | 0–0.05 | 10% |
| Ramp-up | 500–2000 | 0–0.15 | 20% |
| Full | 2000–5000 | 0–0.25 | 30% |
| Hardening | 5000–8000 | 0–0.35 | 40% |

## Место в пайплайне

```
Phase 1 → Phase 2 → Phase 3 → Phase 2b → Phase 4 → ...
  VAE      Decoder   DUS        Robust     Prompt-CA
  Encoder  (clean)   Diffusion  Decoder
```

Phase 3 не нуждается в устойчивом декодере (потери считаются в латентном пространстве, декодер не участвует).
