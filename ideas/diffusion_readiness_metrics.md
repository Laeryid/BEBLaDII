> Автор: AI Agent | Дата: 2026-05-15
> Контекст: Текущие метрики (isotropy, neighbor_recall) фиксируют структуру пространства,
> но не его пригодность для деноизинга. Ниже — конкретные метрики и способы их реализации.

## Проблема

Изотропное пространство необходимо, но недостаточно для диффузии. Нам нужно убедиться в трёх дополнительных свойствах:
1. **Гладкость** — интерполяция между точками пространства семантически непрерывна.
2. **Шумоустойчивость** — малый гауссовский шум не разрушает смысл вектора.
3. **Кластерная согласованность** — семантически близкие примеры близки и в латентном пространстве.

## Метрика 1: Noise Sensitivity (Шумоустойчивость)

**Что измеряет:** Насколько добавление гауссовского шума σ в латентное пространство меняет косинусное сходство с исходным вектором.

**Формула:**
```
NS(σ) = E[ 1 - cos(z, z + ε) ],  ε ~ N(0, σ²·I)
```
Считать для σ ∈ {0.1, 0.3, 0.5, 1.0}. Цель: при σ=0.3 должно быть NS < 0.05.

**Реализация (добавить в validation loop):**
```python
def compute_noise_sensitivity(latent, sigmas=(0.1, 0.3, 0.5, 1.0)):
    """latent: (N, D) активные токены"""
    results = {}
    for sigma in sigmas:
        noise = torch.randn_like(latent) * sigma
        noisy = latent + noise
        cos = F.cosine_similarity(latent, noisy, dim=-1)
        results[f"ns_sigma_{str(sigma).replace('.','_')}"] = (1 - cos).mean().item()
    return results
```

**Диффузионная значимость:** Если NS(0.3) > 0.2, деноизер будет видеть "смысловые прыжки" при малом шаге — это сделает траекторию деноизинга нестабильной.

## Метрика 2: Interpolation Linearity (Линейность интерполяции)

**Что измеряет:** Семантически ли "середина" между двумя латентными векторами.

**Идея:** Берём два валидационных примера A и B. Считаем `z_mid = (z_A + z_B) / 2`. Затем прогоняем оба оригинала и среднее через "верхнюю часть" (слои 20–40) и смотрим: является ли косинусное расстояние `cos(z_mid, z_A)` примерно равным `cos(z_mid, z_B)` (признак симметричной середины), и меньше ли они расстояния `cos(z_A, z_B)` (середина ближе к концам)?

```python
def compute_interpolation_linearity(latents_a, latents_b):
    """
    latents_a, latents_b: (K, D) — пары mean-pooled векторов из K примеров
    """
    z_mid = (latents_a + latents_b) / 2.0
    cos_mid_a = F.cosine_similarity(z_mid, latents_a, dim=-1)
    cos_mid_b = F.cosine_similarity(z_mid, latents_b, dim=-1)
    cos_ab = F.cosine_similarity(latents_a, latents_b, dim=-1)
    # Линейность: середина должна быть ближе к обоим концам, чем они друг к другу
    linearity = ((cos_mid_a + cos_mid_b) / 2 - cos_ab).mean().item()
    return {"interp_linearity": linearity}  # Цель: > 0
```

**Практические ограничения:** Требует пар примеров из одной семантической категории. На старте можно взять соседние чанки одного документа как "связанную пару".

## Метрика 3: Per-Transition Delta-Cos (Диагностика грубости масок)

**Что измеряет:** Насколько хорошо студент копирует учителя на каждом отдельном шаге маски (0→1, 1→2, 2→3) — а не только в суммарном лоссе.

**Зачем:** Если переход 0→1 (грубый, много токенов) имеет значительно **выше** `delta_cos`, чем 2→3 (мелкий), — диагноз "нужно больше масок".

**Реализация:** В текущем коде `compute_delta_loss` уже считает метрики по каждому слою (l20, l30, l40). Нужно также разбить **по индексу перехода** `idx`:

```python
# В train loop, заменить logging в idx==2 на:
for idx in range(3):
    l_delta, m_delta = criterion.compute_delta_loss(...)
    for k, v in m_delta.items():
        # Добавить суффикс перехода: delta_cos_l40_t01, t12, t23
        loss_metrics[f"{k}_t{idx}{idx+1}"] = v
```

**Сигнал тревоги:** Если `delta_cos_l40_t01 >> delta_cos_l40_t23` при большом числе шагов → увеличить число масок с 4 до 8.

**Протокол диагностики (когда запускать и что делать):**

| Условие | Интерпретация | Действие |
|---|---|---|
| `delta_cos_t01 ≈ delta_cos_t12 ≈ delta_cos_t23` | Все переходы выучены одинаково хорошо | Маски достаточно, не трогать |
| `delta_cos_t01 >> delta_cos_t12 >> delta_cos_t23` | Модель учит только "грубые прыжки", теряет мелкие | Увеличить маски с 4 до 8 (добавить отсечки на 12.5%, 37.5%, 62.5%, 87.5%) |
| `delta_cos_t23 >> delta_cos_t01` | Модель лучше справляется с мелкими шагами | Норма для начала обучения, пройдет само |
| Все `delta_cos` < 0.1 после 3000 шагов | Проблема не в гранулярности, а в архитектуре | Проверить корректность `compute_delta_loss`, маски, learning rate |

**Как увеличить число масок (если потребуется):**
1. В `data/mask_variants.py` добавить дополнительные промежуточные варианты (на 25%, 50% уже есть → добавить 12.5%, 37.5%, 62.5%, 87.5%).
2. Обновить `MASK_WEIGHTS` — сохранить суммарный вес = 1.0.
3. Увеличить inner loop с `range(3)` до `range(7)` для `L_delta`.
4. **Без перезапуска чекпоинта** — изменение обратно совместимо.

## Метрика 4: Semantic Cluster Separation (Кластерная согласованность)

**Что измеряет:** Сохраняет ли студент макро-кластеры семантики учителя (математика vs факты vs рассуждения).

**Идея:** Разметить валидационные примеры по типу (можно эвристически, по длине `<think>` блока). Считать inter-cluster / intra-cluster cosine distance ratio. Если student ratio ≥ 0.8 × teacher ratio — пространство семантически согласовано.

**Статус:** Требует разметки валидационного датасета. Сложнее в реализации. Рекомендую отложить до Phase 2.
