# Semantic Context Compression (Token-Level Memory Pruning) для CLM

**Основа идеи:** Вдохновлено концепциями из `HySparse` (Oracle-guided Token Selection) и адаптировано под неавторегрессионную (диффузионную) архитектуру BEBLaDII.

## Суть концепции
Вместо того чтобы хранить в Chunked Latent Memory (CLM) сырые латентные вектора *всех* токенов чанка, мы осуществляем жесткое прореживание (Hard Pruning) на этапе записи в память. 
Латентный энкодер выступает в роли "оракула", выделяя наиболее семантически значимые токены (hub tokens) на основе матриц внимания с последних слоев. В базу CLM сохраняются только Top-K (например, 20-30%) самых "тяжелых" токенов. Остальные 70-80% (пунктуация, стоп-слова, грамматический шум) отбрасываются.

## Преимущества для BEBLaDII
В диффузионной архитектуре BEBLaDII нет классического растущего авторегрессионного KV-кэша. Контекст подается в Cross-Attention (CA) слои единым статичным тензором `[Batch, SeqLen, Dim]`.

1. **Радикальное сжатие памяти**: Объем хранимых тензоров контекста в CLM падает в 3-5 раз, позволяя радикально увеличить объем доступной истории/памяти агента без OOM.
2. **Линейное ускорение CA**: Сложность вычислений в CA слоях напрямую зависит от длины последовательности памяти ($O(N_{query} \times N_{memory})$). Уменьшение $N_{memory}$ в несколько раз дает пропорциональный прирост скорости инференса (или квадратичный, если оптимизация затрагивает обе стороны).
3. **Снижение шума (галлюцинаций)**: Внимание фокусируется только на плотной, насыщенной смыслом информации.

## Требования к обучению (Предотвращение Distribution Shift)
Математически CA-слои не зависят от длины последовательности. Однако, чтобы модель (например, в Phase 4) научилась корректно извлекать смысл из такого "швейцарского сыра", необходимо внедрить прореживание токенов непосредственно в пайплайн тренировки.

**Решение:**
В процессе обучения с определенной вероятностью (например, 50%) маскировать/удалять нерелевантные токены из контекста, подаваемого в CA-слои. Это заставит модель стать устойчивой (robust) к разреженному контексту, и на инференсе сжатие будет работать "из коробки" (Zero-shot) без падения метрик.
