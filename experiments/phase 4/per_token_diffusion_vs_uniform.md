# Идея: Per-Token Диффузия и Иерархическое Проявление

**Дата обсуждения:** 2026-08-24
**Контекст:** Phase 3 в процессе обучения (каноническая сферическая диффузия, ADR-060)

---

## Исходная концепция

Изначально диффузия задумывалась не как «шум на всю фразу», а как **маскирование + проявление**:
- Сначала проявляются опорные (якорные) токены.
- Затем — детальные, зависящие от уже проявленных.
- Уровень шума каждого токена управляется оценкой уверенности (ConfidenceHead).
- Финальное применение: скармливать модели JSON с пропусками, пусть заполняет только их.

---

## Ключевой вывод обсуждения

### Текущий подход (uniform t) — корректный, но ограниченный

- Все токены одной фразы зашумляются одинаковым 	.
- AdaLN кондиционирует **весь слой** одним значением 	 => нет per-token семантики.
- Модель никогда не видит смешанного состояния в одной последовательности:
  [token_clean, token_noisy, token_clean, token_noisy].
- **Следствие:** обученная модель не сможет «из коробки» различить уже-раскрытые токены
  от зашумлённых в одной фразе. Это не обученный навык, а лишь побочный эффект геометрии.

### Почему cos_h39_t_high в Phase 3 — бессмысленная метрика для оценки готовности

При uniform t все соседи одинаково зашумлены. При t=0.9:

    mu(0.9) = cos(0.9 * pi/2) ≈ 0.16
    SNR = mu^2 / sigma^2 ≈ 0.026

Модель видит: [шум, шум, шум]. Нет ни локального сигнала, ни контекстуального.
**Высокий cos_h39_t_high принципиально недостижим в Phase 3** — не из-за слабости
модели, а из-за отсутствия информации. Требовать его как порог перехода — неверно.

### Per-token подход открывает принципиально другой режим

При per-token t модель видит:

    token[0]: t=0.05  =>  z_noisy ≈ z_clean  (несёт информацию — "якорь")
    token[1]: t=0.95  =>  z_noisy ≈ random   (нет локального сигнала)
    token[2]: t=0.08  =>  z_noisy ≈ z_clean  (несёт информацию — "якорь")

Для token[1] модель решает задачу:

    P(z_clean[1] | z_noisy[1]=шум, z_clean[0], z_clean[2])

Это **условное предсказание по контексту** — именно то, для чего создан двунаправленный
ModernBERT. Контекст восстанавливает сигнал, которого нет локально.
Phase 3.5 не дополняет Phase 3 — она открывает работу при высоком локальном шуме.

### Разрыв circular dependency

Исходная ловушка:

    ConfidenceHead нужен => чтобы знать per-token t
    per-token t нужен    => чтобы обучить модель, умеющую использовать ConfidenceHead

**Решение:** ConfidenceHead НЕ нужен во время обучения per-token диффузии.
Достаточно случайной маски:

    t_per_token = torch.rand(B, T) * (t_max - t_min) + t_min

Модель учится работать со смешанными состояниями без цикличной зависимости.
ConfidenceHead обучается ПОСЛЕ как отдельная предсказывающая голова:

    confidence(token_i) = cos_sim(DUS_output[i], z_clean[i])

Голова учится предсказывать качество восстановления до того, как известен z_clean.

### Архитектурное изменение: per-token AdaLN

Текущий AdaLN: t_emb [B, dim] => shift/scale [B, 1, D] (broadcast на весь T).
Нужный AdaLN:  t_emb [B, T, dim] => shift/scale [B, T, D] (per-token).

Изменение минимальное — та же архитектура, добавляется измерение T.
Совместимо с загруженными весами Phase 3 через fine-tune.

### Следствие для Min-SNR

В Phase 3 Min-SNR downweights высокий t — корректно (там нет сигнала при uniform t).
В Phase 3.5 Min-SNR нужно убрать или инвертировать: токены при высоком t теперь
информативны через контекст, их недообучение создаёт мёртвую зону именно там, где
модель должна научиться самому важному.

## Сравнение задач по фазам

| | Phase 3 | Phase 3.5 |
|---|---|---|
| Задача | P(z_clean | z_noisy, t) — изолированный денойзинг | P(z_clean[i] | z_noisy[i], context_clean) — контекстный |
| Высокий t | Нет сигнала, нет смысла | Основная задача — именно здесь |
| AdaLN | [B, 1, D] broadcast | [B, T, D] per-token |
| Min-SNR | Нужен (downweight высокий t) | Убрать |
| Критерий готовности перехода | cos_h39_t_low > 0.80 | — |

---

## Предлагаемый порядок фаз (пересмотр плана)

    Phase 3   Базовый денойзинг (uniform t)
                 | Критерий: cos_h39_t_LOW > 0.80 (модель знает, что такое "чистый" латент)
                 |
    Phase 3.5a  Per-token AdaLN + random t_i на токен (дообучение DUS)
                 | Модель учится: использовать соседей-якорей для восстановления зашумлённых
                 |
    Phase 3.5b  ConfidenceHead: учится предсказывать cos_sim(output, z_clean) per-token
                 | Голова умеет измерять неопределённость без знания z_clean
                 |
    Phase 4    CA_Prompt поверх модели, которая уже понимает per-token уверенность

Оркестратор тогда получает осмысленный сигнал: какие токены кристаллизовались,
какие — ещё нет, и именно их гнать на следующий шаг диффузии.

---

## JSON-инпейнтинг: два пути

После Phase 3.5 оба пути валидны:

1. **CA_Prompt (Phase 4):** JSON-скелет подаётся как промпт через cross-attention.
   Модель заполняет все значения из шума, обусловленная на схему. Проще в реализации.

2. **Истинный инпейнтинг (через per-token t):** ключи JSON => t=0 (якоря),
   значения => t=1 (шум). Модель заполняет пропуски, опираясь на ключи как контекст.
   Возможен только после Phase 3.5.
