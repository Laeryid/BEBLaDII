# Phase 6: Prompt Conditioning (CA_Prompt)

**Дата:** 2026-09-23  
**Статус:** Планирование  
**Предшествует:** Phase 5 (Sensor Ensemble + Orchestrator)  
**Цель:** Обучить слои `CA_Prompt` инжектировать семантику вопроса (промпта) в диффузионный процесс, обусловливая денойзинг «холста ответа».

---

## 1. Ключевая концепция: от Phase 4 к Phase 6

### Что переиспользуется из Phase 4
- Иерархическое зашумление (t_global + t_actual per-token)
- Loss без Min-SNR
- AdaLN per-token кондиционирование

> **Механизм «лжецов» (False Confident tokens) из Phase 4 — убран.**  
> В Ph4 он был необходим: единственным контекстом были шумные соседи, и без искусственного конфликта модель не получала сигнала «не доверяй уверенности». В Ph6 этот конфликт возникает органически — CA_Prompt несёт семантику вопроса, которая сама по себе может противоречить локальной уверенности токена. Конструировать его искусственно не нужно, а обучение на нём создавало бы ложный domain gap.

### Принципиальное изменение: замена t_reported

В Phase 4 `t_reported` был либо честным случайным, либо ложным — в обоих случаях он был **не связан с реальным поведением на инференсе**, что создавало domain gap.

В Phase 6 `t_reported` вычисляется через **Sensor Ensemble** (Phase 5):

```
Phase 4: t_reported = random / fake  → domain gap
Phase 6: t_reported = RawDProx(h39_i)  [Sensor Ensemble] → идентично инференсу
```

Зашумление при этом по-прежнему случайное (`t_actual ~ U(0, 1)`). Sensor Ensemble вычисляет оценку уверенности на основе зашумлённого состояния — так же, как он будет делать это при инференсе.

> **Важно:** Диапазон t_actual теперь включает 1.0 (ограничение `t_global <= 0.99` из Ph4 снимается). Это нужно, потому что генерация ответа стартует из чистого шума — модель должна уметь работать с полным диапазоном.

---

## 2. Постановка задачи

### Формат данных

Каждый обучающий сэмпл — пара Q&A:
- **Вопрос (Q):** подаётся как ключи/значения в `CA_Prompt` через Latent Encoder
- **Ответ (A):** денойзится на «холсте» диффузии

```
z_question = LatentEncoder(Q)  # [B, T_q, D] — ключи/значения CA
z_answer   = LatentEncoder(A)  # [B, T_a, D] — холст для денойзинга
```

Модель учится буквально **генерировать ответ** из шума, обусловленная вопросом через Cross-Attention. Это не преобразование холста — это генерация с нуля.

### Датасет

Упор на **логику и рассуждение**, не на фактологию. Ответ должен **выводиться** из вопроса, а не извлекаться из базы знаний. Модель не может быть начитанной (латентное пространство ограничено), но должна быть сообразительной.

#### Требования к данным

| Параметр | Значение |
|---|---|
| Формат | Строгие пары Q→A (не диалог-цепочка, не монолог) |
| Длина ответа | **50–500 токенов** (не обрывки, не эссе) |
| Длина вопроса | **1–4 предложения** (конкретный, но содержательный Q даёт богатый K/V сигнал) |
| Содержание | Семантика + структура мысли; без фактологии, URL, кода (если не нужен) |
| Маркеры качества | Наличие логических переходов («следовательно», «поэтому», «значит» или эквивалентов) |
| Исключить | Wikipedia-style текст, справочные ответы, однострочники (<50 токенов), `\boxed{...}`-only ответы |

> **Важно:** обрезка ответов до 500 токенов **недопустима** — мы обучаем модель генерировать цельную мысль. Пары с более длинными ответами отфильтровываются целиком, не усекаются.

#### Стратегия работы с CoT-датасетами

OpenThoughts и Magpie-Reasoning содержат полные цепочки рассуждений длиной несколько тысяч токенов. **Мы не фильтруем такие примеры — мы отрезаем CoT и оставляем только финальный ответ.**

Обоснование: CoT — черновик мысли учителя. Нам нужна *цель*: что представляет собой хороший ответ на данный вопрос. Диффузия учится приходить к этой цели своим путём через CA_Prompt, а не имитировать цепочку рассуждений.

```
Полный сэмпл:  Q | <think> ... длинная цепочка ... </think> | Финальный ответ
Используем:    Q |                                             Финальный ответ
```

**Что считать «финальным ответом»** в зависимости от формата:
- После тега `</think>` или `</thinking>` — весь текст после него
- После `#### Solution` / `**Answer:**` — соответствующий раздел
- Если структуры нет — последний абзац (эвристика)

**Риск:** в ряде задач «финальный ответ» = `The answer is C` или `\boxed{42}` — слишком короткий для обучения. Фильтр по минимальной длине (≥50 токенов) применяется уже *после* извлечения.

> **Реализация:** логика извлечения специфична для каждого источника и решается отдельно при подготовке каждого датасета.

#### Таксономия reasoning-паттернов (минимальное покрытие)

CA_Prompt должен обобщить как минимум 7–8 базовых типов рассуждения:

| Тип | Пример |
|---|---|
| Дедуктивный | «Если A→B и A, то...» |
| Каузальный | «Почему X происходит?» |
| Сравнительный | «В чём разница между X и Y?» |
| Процедурный | «Как решить задачу X?» |
| Оценочный | «Что лучше: X или Y и почему?» |
| Аналогический | «X — это как Y, потому что...» |
| Математический | «Задача → пошаговое решение» |

#### Базовые знания и идентичность (Identity & Architecture Alignment)

Несмотря на общее правило «упор на логику, а не фактологию», в Phase 6 внедряется минимальный, но критически важный объем встроенных знаний — **идентичность модели**. 

**Обоснование:**
Знание своей архитектуры (BEBLaDII, Latent Diffusion) — это не просто рядовые факты, а **базовая точка отсчета (anchor) для выстраивания логики ограничений (Alignment)**. Модель должна понимать свою природу, чтобы корректно обосновывать свои возможности и лимиты. Запрашивать собственное имя или архитектуру из внешней памяти (CLM, Phase 7) — концептуально и архитектурно избыточно.

Эти знания внедряются не как сухие факты, а через структурные рассуждения о принципах своей работы:
- **Плохо:** «Я BEBLaDII.»
- **Хорошо:** «Я BEBLaDII, модель на базе Latent Diffusion. В отличие от авторегрессионных моделей, я не предсказываю текст по словам, а формирую непрерывные представления в латентном пространстве, итеративно устраняя шум...»

Такие данные (в объеме небольшого сета высококачественных Q/A) обеспечат внутреннюю стабильность "личности" модели до подключения RAG.

## 3. Архитектура CA_Prompt

### 3.1 CAPromptLayer — финализированная архитектура

Каждый `CAPromptLayer` — самостоятельный блок (не модификация существующего слоя DUS), состоящий из двух подблоков: **Cross-Attention** (CA) и **Self-Attention** (SA). Вставляется в DUS после указанных слоёв, DUS при этом заморожен.

```
x ──► Pre-LN ──► q_proj ──────────────────────────────────┐
                                                           ├──► SDPA ──► out_proj ──► tanh(gate)·warmup ──► + ──► x'
z_q ─────────► kv_proj ──► K ─────────────────────────────┤                                                    │
                        └──────────────────────────────── V┘                                                    │
x' ──► Pre-LN ──► q_proj_sa ──────────────────────────────┐
                                                           ├──► SDPA ──► out_proj_sa ──► warmup ──► + ──► x''
x' ──► Pre-LN ──► kv_proj_sa ──► K ───────────────────────┤
                             └───────────────────────── V ─┘
```

#### Ключевые решения

**Q–(K=V) sharing** (arXiv:2606.04032, Kayyam et al., 2025):  
И в CA, и в SA используется одна матрица для проекции K и V. Экспериментально подтверждено, что K и V занимают схожее репрезентационное пространство; деградация perplexity ~3.1% при экономии 25% параметров в блоке.

- CA: Q из `x`, K=V из `z_question` — одна матрица `kv_proj`
- SA: Q из `x`, K=V из `x` — одна матрица `kv_proj_sa`
- Q остаётся отдельным в обоих случаях → асимметрия внимания сохраняется

**Полное (global) внимание:** CA смотрит на все токены вопроса целиком. Локальное внимание не имеет смысла для cross-attention: токены холста должны видеть весь промпт.

**Pre-LN:** соответствует стилю ModernBERT, на котором обучен DUS. Отдельный LayerNorm перед каждым подблоком.

**Learnable gate + warmup:** gate инициализируется нулём, обёрнут в `tanh` (ограничение |gate| ≤ 1, симметрия, градиент = 1 при init). `warmup_factor` — внешний скалярный коэффициент 0→1, применяется ко всему выходу CAPromptLayer.

```python
class CAPromptLayer(nn.Module):
    def __init__(self, D: int, H: int):
        super().__init__()
        # Cross-Attention
        self.norm_ca    = nn.LayerNorm(D)
        self.q_proj     = nn.Linear(D, D)
        self.kv_proj    = nn.Linear(D, D)   # K=V — одна матрица
        self.out_proj   = nn.Linear(D, D)
        self.gate       = nn.Parameter(torch.zeros(D))

        # Self-Attention
        self.norm_sa    = nn.LayerNorm(D)
        self.q_proj_sa  = nn.Linear(D, D)
        self.kv_proj_sa = nn.Linear(D, D)   # K=V — одна матрица
        self.out_proj_sa = nn.Linear(D, D)

    def forward(self, x, z_q, warmup: float = 1.0):
        # Cross-Attention
        normed = self.norm_ca(x)
        q      = self.q_proj(normed)
        kv     = self.kv_proj(z_q)
        ca_out = F.scaled_dot_product_attention(q, kv, kv)
        x = x + warmup * torch.tanh(self.gate) * self.out_proj(ca_out)

        # Self-Attention
        normed = self.norm_sa(x)
        q_sa   = self.q_proj_sa(normed)
        kv_sa  = self.kv_proj_sa(normed)
        sa_out = F.scaled_dot_product_attention(q_sa, kv_sa, kv_sa)
        x = x + warmup * self.out_proj_sa(sa_out)

        return x
```

#### Параметры одного CAPromptLayer при D=1024, H=16

| Матрица | Размер |
|---|---|
| q\_proj, kv\_proj, out\_proj (CA) | 3 × 1024² = 3.1M |
| q\_proj\_sa, kv\_proj\_sa, out\_proj\_sa (SA) | 3 × 1024² = 3.1M |
| norm\_ca, norm\_sa, gate | ~6K |
| **Итого** | **~6.3M** |

Всего 3 слоя × 6.3M = **~18.9M обучаемых параметров** (весь DUS заморожен).

### 3.2 Места интеграции

Три равномерно распределённые точки в 40-слойном DUS:

```
DUS layer 12 → CAPromptLayer #1
DUS layer 24 → CAPromptLayer #2
DUS layer 36 → CAPromptLayer #3
```

Равномерное распределение выбрано как baseline. Ablation по позициям — в Phase 6b.

### 3.3 Кодирование вопроса

Latent Encoder обрабатывает токены вопроса **независимо** (per-token, без cross-token attention) → ограничений по длине промпта нет. Связь между токенами вопроса возникает в CA: токены холста ответа агрегируют по всем K/V вопроса одновременно.

```python
with torch.no_grad():
    z_question    = latent_encoder(Q_tokens)   # [B, T_q, D], detach
    z_answer_clean = latent_encoder(A_tokens)  # [B, T_a, D], detach
```

Градиент через энкодер не течёт ни для вопроса, ни для ответа.

### 3.4 Инициализация и разморозка

- Все веса CA/SA инициализируются случайно (Xavier uniform)
- `gate` инициализируется нулём → `tanh(0) = 0`, нет влияния на DUS при `warmup=0`
- DUS загружается из Phase 5, **полностью заморожен** (Phase 6a)
- `warmup_factor`: линейный рост 0→1 за первые N шагов (N = ~500–1000, подобрать эмпирически)

## 4. Схема зашумления

```python
# t_actual — честное случайное зашумление (полный диапазон, включая 1.0)
t_actual = torch.rand(B, T_a)   # U(0, 1]

# Зашумление холста ответа
z_noisy = slerp(z_answer_clean, noise, t_actual)

# Прямой проход DUS (+ z_question через CA_Prompt)
h39, z_pred = DUS(z_noisy, z_question=z_question, t_reported=PLACEHOLDER)

# t_reported = RawDProx из Sensor Ensemble (идентично инференсу)
with torch.no_grad():
    t_reported = sensor_ensemble.raw_dprox(h39.detach())  # [B, T_a]

# Loss считается относительно z_answer_clean по t_actual (не t_reported)
loss = angular_loss(z_pred, z_answer_clean, t_actual)
```

> **Связь обучения и инференса:** `t_reported = RawDProx` одинаков в обоих режимах — это и есть ключевой принцип Phase 6 (замена domain gap из Ph4). DUS заморожен, поэтому двойной forward pass не нужен: основной learning signal CA_Prompt идёт через attention к `z_question`, а не через AdaLN.

## 5. Функция потерь

```python
# Angular loss (из Ph4, без Min-SNR), alpha взвешивает по t_actual
loss_denoise = angular_loss(z_pred, z_answer_clean, t_actual, alpha=2.0)

# l_isolation в Phase 6a НЕ используется:
# промпт уже даёт глобальный контекст — потребность изолироваться от шумных
# соседей снижена. Добавить, если появится регрессия на метриках Ph4.

loss = loss_denoise
```

## 6. Протокол инференса

### Инициализация холста

Генерация ответа стартует из **чистого шума на сфере**:

```python
noise = torch.randn(B, T_a, D)
z_canvas = F.normalize(noise, dim=-1)   # [B, T_a, D] — точки на единичной сфере
```

### Шаги денойзинга

**25 шагов**, расписание — **равномерное** (`t` от 1.0 до 0.0):

```python
steps = torch.linspace(1.0, 0.0, 26)[:-1]  # [t=1.0, ..., t≈0.04]

for t in steps:
    t_tensor = torch.full((B, T_a), t)
    with torch.no_grad():
        t_reported = sensor_ensemble.raw_dprox(z_canvas)   # [B, T_a]
        h39, z_pred = DUS(z_canvas, z_question=z_question, t_reported=t_reported)
    z_canvas = slerp(z_canvas, z_pred, step=1/25)
```

> **Расписание:** равномерное — baseline. В дальнейшем Оркестратор (Phase 5) сможет адаптировать шаг на основе сигналов Sensor Ensemble (например, замедляться при высоком ConflictSim). Phase 6 это не реализует.

### Результат

После 25 шагов `z_canvas` — латентное представление ответа, готовое к декодированию.

### Батчинг (TPU-first)

Форма батча диктуется **ограничениями TPU**, а не фиксированными значениями. Стратегия:
- Статические формы (`[B, T_q, D]`, `[B, T_a, D]`) — XLA требует compile-time shapes
- PAD-токены в `z_question` маскируются при CA (`key_padding_mask` в SDPA)
- Конкретные значения `B`, `T_q`, `T_a` определяются по OOM-границе при запуске

## 7. Стратегия размораживания (curriculum разморозки)

```
Phase 6a: DUS заморожен, только CA_Prompt обучаются
           Оцениваем потолок влияния CA на качество денойзинга
           Критерий: prompt_sensitivity растёт, базовые метрики Ph5 не деградируют
           |
Phase 6b: Размораживаем 1 слой DUS сразу после каждого CA_Prompt
           Есть ли улучшение сверх потолка 6a?
           |
Phase 6c: Постепенная разморозка дальше (по 1-2 слоя), если 6b полезна
```

### Метрики

| Метрика | Смысл | Цель |
|---------|-------|------|
| `cos_denoise` | cos(z_pred, z_answer_clean) при t=0.1 | Выше baseline Phase 5 |
| `prompt_sensitivity` | dist(z_pred(Q1), z_pred(Q2)) при одинаковом шумном холсте, разных Q | Должна расти |
| `prompt_alignment` | cos(z_pred, z_answer_clean) - cos(z_pred_noprompt, z_answer_clean) | delta > 0 |
| `iso`, `rank1` | Из Phase 4/5 | Не должны деградировать |
